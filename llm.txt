# Global News Scraper PHP

> PHP client for scraping full-text news articles from 300+ sources worldwide via Apify: switch on any sources, get one merged Laravel collection of typed articles.

Key facts:
- Package: `bitesizedinsights/global-news-scraper`
- Install: `composer require bitesizedinsights/global-news-scraper`
- PHP: ^8.3, Guzzle ^7 || ^8, illuminate/collections
- Namespace: `GlobalNewsScraper`
- Entry class: `GlobalNewsScraper\Client`
- Auth: Apify API token, set via `Client::setApifyKey()`, falls back to env `APIFY_API_TOKEN` or `APIFY_TOKEN`

## Docs
- [README](https://github.com/bitesizedinsights/global-news-scraper-php/blob/master/README.md): usage
- [Actors](https://apify.com/bite-sized-insights): the underlying Apify collector Actors

## API
- `Client::__construct(?Config $config = null, ?GuzzleHttp\ClientInterface $http = null, ?Closure $sleeper = null, ?Closure $onRetry = null)` - `$sleeper` waits between retries (tests)
- `Client::setApifyKey(string $apiKey): static` - sets the Apify API key; without it `APIFY_API_TOKEN` or `APIFY_TOKEN` is read from the environment, and `MissingApiKeyException` is thrown on the first API call if neither is set
- `Client::scrape(array|Collection|Source|SourceGroup|Collector $sources, ?string $searchQuery = null, DateTimeInterface|string|null $startDate = null, DateTimeInterface|string|null $endDate = null, ?int $limit = null, bool $withSentiment = false, bool $withTags = false, bool $withSummary = false, bool $with5w1h = false, bool $withLanguageDetection = false, bool $withFixText = false, ?int $runTimeout = null): ScrapeResult` - `$sources` is a `Source`, a `SourceGroup` (see Enums), a `Collector` or an array/collection mixing them (groups are expanded, duplicates removed; large groups start many billed collector runs, so check `plan()` and set `$limit`); maps sources back to collector Actors (fewest collectors, ties go to the country collector), runs them separately and concurrently, merges and deduplicates the articles by URL (ignoring `http`/`https`, `www.`, default ports, trailing slashes, in-page fragments, query parameter order and tracking parameters (`utm_*`, `fbclid`, `gclid` and similar); the first article is kept with its URL unchanged); `$searchQuery` (1-100 chars) keeps only articles whose title, text or URL contain the keyword; `$startDate`/`$endDate` (`YYYY-MM-DD` or date object) bound the publication date (start not in the future, end not older than 5 years and not before start); `$limit` (0 to 10000, 0 = unlimited, above 10000 throws like the Actors' maximum, null = Actor default 100) is the maximum per collector run, not for the merged result; `$withSentiment`, `$withTags`, `$withSummary`, `$with5w1h`, `$withLanguageDetection`, `$withFixText` add optional per-article analysis to `Article::$sentiment`, `$tags`, `$summary`, `$fiveW1h`, `$detectedLanguage`, `$fixedText` (raw `?array`, null unless requested and successful)
- `Client::start(<same arguments as scrape()>): RunBatch` - starts the runs of `plan()` without waiting; they keep running and are billed. A failed start never throws: `RunBatch::$errors` gets a `CollectorError` and the other handles are returned; a start that may have reached Apify is never repeated (after a 5xx, timeout or unreadable answer the run may exist without a handle). After the first 402 no further run is started (`Not started: ...`); `SpendingLimitException` is thrown only when not one run was started. `Config::$maxConcurrency` limits simultaneous start requests only, all started runs execute at once. Default Apify run time limit = `Config::$timeout`, as in `scrape()`
- `Client::getRun(Run|string $run): Run` - one lookup (`GET /actor-runs/{id}`), no waiting. A bare ID needs a second request (`GET /acts/{actId}`, cached per client) to identify the collector; `ApiException` for unknown runs (code 404), for runs of an Actor that is no collector of this library, and for a missing or unknown status. A `Run` handle's collector is taken as it is
- `Client::wait(RunBatch|Run|string|array|Collection $runs, ?int $timeout = null): RunBatch` - arrays/collections mix `Run` and ID strings, duplicates by ID used once; waits until all runs are final or the timeout (all runs together, seconds; null = `Config::$timeout`, 0 = one lookup per unfinished run, negative throws InvalidInputException) expires. Never aborts, never throws for a failed run or an expired timeout (check `isFinished()`/`isSuccessful()`); a failed lookup of a handle keeps the last state, sets `Run::$lookupError` and stops polling that run for this call; each unfinished run is looked up at least once, so the call can exceed `timeout`. Keeps the batch's start errors. Throws only for invalid input, a missing key or an unresolvable bare ID
- `Client::results(RunBatch|Run|string|array|Collection $runs): ScrapeResult` - no waiting, no abort; merges and deduplicates like `scrape()` (earlier run wins). Failed/aborted/timed-out runs (`Actor run ended with status X[: reason]`), unfinished runs (`Actor run is not finished (status X): call wait() and read the results again`) and unreadable runs or datasets become `CollectorError` with `runId`, after the batch's start errors. An unfinished handle is looked up once. `SpendingLimitException` only when HTTP 402 occurred while reading and no article was read
- Run IDs are validated (`A-Z a-z 0-9 _ ~ -`, 1 to 64) by `getRun()`, `wait()`, `results()` and `abort()` before any request (`InvalidInputException`)
- `Client::abort(Run|string $run): void` - aborts an Apify run (`POST /actor-runs/{id}/abort`); throws `ApiException`/`RateLimitException`. When `Config::$timeout` expires, `scrape()` aborts every still pending run best effort (10 s max, no retries) and the collector error reads `Actor run did not finish within N seconds and was aborted` (without `and was aborted` if the abort failed); no abort for FAILED/ABORTED/TIMED-OUT runs, and for rate limits or connection errors only when they use up the timeout while polling
- `Client::plan(array|Collection|Source|SourceGroup|Collector $sources): RunPlan[]` - the collector runs `scrape()` would start, no request is sent
- `Config(string $baseUrl = 'https://api.apify.com/v2', int $timeout = 900, int $requestTimeout = 90, int $maxConcurrency = 2, int $maxRetries = 3, float $retryBaseDelay = 1.0, float $retryMaxDelay = 30.0, ?int $runTimeout = null)` - runTimeout is Apify's own run time limit in seconds, sent as the `timeout` query of the run-start POST only (never polling, abort or dataset requests); null = `timeout` (so the platform stops a run when the client gave up), 0 = send nothing and keep the Actor default, negative throws InvalidArgumentException; `scrape(..., ?int $runTimeout = null)` (last argument) overrides it per call (0 = Actor default, negative throws InvalidInputException); separate from `requestTimeout`;  retries use exponential backoff with jitter and honour `Retry-After` (seconds or HTTP date): 429, 5xx and connection failures are retried; the run-start POST only after a 429 or a failed connection, never after a 5xx or timeout (billing); `maxRetries: 0` disables retrying
- Retry safety and time limit: the run-start POST is repeated only after a 429 or a connection failure that shows the request was never sent (cURL errors 5, 6, 7, 35, Guzzle 8 `ConnectTimeoutException`, or a non-timeout connection failure without a cURL code; on Guzzle 7 never after cURL error 28); `Retry-After` is honoured on 429 and 503 (above `retryMaxDelay` the error is thrown); 408 and other 4xx are never retried. `Config::$timeout` covers the run start, wait and retries of each collector run: a retry whose wait would pass it is skipped, each request timeout is cut to the time left plus 5 s, reading the results of a successful run keeps at least 30 s, and if polling fails because the time is used up the run is aborted best effort and the last request's error is thrown
- Retry hook: the fourth `Client::__construct` argument `?Closure $onRetry` is called with a `RetryEvent` (`GlobalNewsScraper\DTO\RetryEvent`) before the wait of each retry; final readonly: `string $method`, `string $path` (IDs masked as `{id}`), `int $retry` (from 1), `int $maxRetries`, `float $delay`, `?int $status`, `?int $curlError`, `message(): string`; holds no token, query or body; what the callback throws is ignored. A `Retry-After` above `retryMaxDelay` is never clamped: the error is thrown at once.
- DTOs (all `final readonly`; `Article`, `ScrapeResult`, `CollectorError`, `RunPlan`, `Run`, `RunBatch` implement JsonSerializable and have toArray() in the Actor's snake_case shape plus `collection` on Article, and fromArray(toArray()) restores them):
  - `ScrapeResult`: entries: Collection<int, Article>, errors: Collection<int, CollectorError>; helpers hasErrors(), isComplete()
  - `Article` (`fromArray(array, ?string $collection = null)`, collection falls back to the array's `collection` key): url: string, collection: string (collector key, e.g. `us`), title: ?string, authors: string[], datePublish: ?string, description: ?string, text: string, language: ?string, imageUrl: ?string, sourceDomain: string, type: ArticleType, error: ?string; helpers isArticle(), hasEnrichment()
  - `CollectorError`: collector: Collector, message: string, runId: ?string (Apify run ID when known, e.g. for `Client::abort()`; toArray() emits `runId` only when set), statusMessage: ?string (Actor's own reason of a failed run, raw, max 2000 chars; toArray() emits it only when set)
  - `RunPlan`: collector: Collector, sources: Source[]
  - `Run` (handle of one collector run): collector: Collector, id: string, status: ?RunStatus (null only when a start answer had no known status), defaultDatasetId: ?string, startedAt: ?string, finishedAt: ?string, statusMessage: ?string (raw, max 2000 chars), lookupError: ?string (set by wait()); helpers isFinished(), isSuccessful()
  - `RunBatch`: runs: Collection<int, Run> (plan order), errors: Collection<int, CollectorError> (collectors without a handle); runIds(): string[], hasErrors(), isFinished() (no run pending), isSuccessful() (no errors and every run succeeded)
- Enums:
  - `Source`: one case per news outlet (900+), value is the Actor input key, e.g. NewYorkTimes ('new_york_times'); label(), collectors()
  - `Collector`: Es, Fr, Id, JpEn, Latam, Mx, Sea, Uk, Us, Arab, TwEn, Ng, Scandinavian, Jp, KrKo, Th, Vn, Pl, Tr, It, De, Au, Br, Ca, Ch, Gt, IdEn, Il, IlEn, In, InEn, KrEn, Kurdish, Nl, Ph, Pk, PkEn, Py, Tw, InFinance, UkFinance, UkTech, UsFinance, UsTech, Defense, EnergyClimate, StartupsVc, SupplyChain, Biopharma, Insurance; value is the collection key (`jp-en`); actorId() (public Apify Actor ID `bite-sized-insights/<slug>`), sources(), actorName() (source-repo name `news-collector-<value>`, e.g. `news-collector-us`), isRegional()
  - `SourceGroup` (31 cases, value is the language code): All ('all', every source), English ('en'), Spanish ('es'), French ('fr'), Portuguese ('pt'), Indonesian ('id'), Arabic ('ar'), Danish ('da'), Norwegian ('no'), Swedish ('sv'), Japanese ('ja'), Korean ('ko'), Thai ('th'), Vietnamese ('vi'), Polish ('pl'), Turkish ('tr'), Italian ('it'), German ('de'), Dutch ('nl'), Hebrew ('he'), Hindi ('hi'), Chinese ('zh', Traditional/Taiwan), Urdu ('ur'), Pashto ('ps'), Sindhi ('sd'), Tagalog ('tl'), Ilocano ('ilo'), Hiligaynon ('hil'), Bikol ('bcl'), Kurmanji ('kmr'), Sorani ('ckb'), Zazaki ('zza'); `label()` returns the display name (`All sources` for All, otherwise the case name, e.g. `Spanish`); `sources()` returns the group's `Source` list in `Source` order
  - `ArticleType`: Article ('article'), Video ('video'), Audio ('audio')
  - `RunStatus`: Ready ('READY'), Running ('RUNNING'), Succeeded ('SUCCEEDED'), Failed ('FAILED'), Aborting ('ABORTING'), Aborted ('ABORTED'), TimingOut ('TIMING-OUT'), TimedOut ('TIMED-OUT'); isFinished(), isFailure()
- Exceptions: `InvalidInputException` (extends InvalidArgumentException; empty or non-Source sources, an invalid option or a malformed run ID; thrown before any request), `MissingApiKeyException` (extends ApiException), `ApiException` (`$runId` when known, `$statusMessage` = the Actor's reason of a failed run; the message then reads `Actor run ended with status X: <reason>`, control characters stripped, reason capped at 500 chars), `RateLimitException` (retryAfter), `SpendingLimitException` (extends ApiException; HTTP 402, never retried, code 402, `$errorType` = Apify error type or null; in `scrape()` no further collector run starts after the first 402, skipped ones become `CollectorError` `Not started: ...`; partial articles are returned with CollectorError entries saying `Apify spending limit reached (HTTP 402)`, and only when no article was collected at all `scrape()` throws it). Failing collector runs are not thrown but returned in `ScrapeResult::$errors`. Exception messages never contain the request URL, query string, headers or raw response body: they read `Apify API request failed (HTTP 502): <Apify error type>: <Apify error message>` (parsed from the JSON error body, parts capped at 500 chars; without a usable body just `Apify API request failed (HTTP 502)`), transport failures `Apify API request failed: connection error|timed out (ConnectException)`, 429 `Apify API rate limit reached (retry after N seconds)`, 402 `Apify spending limit reached (HTTP 402): <message>`. The raw body (control characters stripped, max 2000 chars) is `ApiException::$responseBody` (`?string`, last optional constructor parameter, also on RateLimitException/SpendingLimitException); `getPrevious()` is the Guzzle exception whose message contains the URL.

## Example
```php
use GlobalNewsScraper\Client;
use GlobalNewsScraper\Source;

$client = (new Client())->setApifyKey(getenv('APIFY_API_TOKEN'));
$result = $client->scrape([Source::NewYorkTimes, Source::BbcNews]);
$result->entries->groupBy('collection')->map->count(); // ['us' => 12, 'uk' => 9]

// Async: start, store the handles, read later
$batch = $client->start([Source::NewYorkTimes, Source::BbcNews]);
$stored = json_encode($batch);
$batch = $client->wait(GlobalNewsScraper\DTO\RunBatch::fromArray(json_decode($stored, true)), 300);
if ($batch->isFinished()) {
    $result = $client->results($batch);
}
```
- `SourceGroup::sources(): Source[]` and `Source::language(): SourceGroup` - every source has exactly one language group
- The full list of all sources (one `Source` case each, with display name via `Source::label()`) is the generated `src/Source.php` (case name = value) plus `src/SourceMap.php` (`LABELS`, `BY_COLLECTOR`); the README section "News Sources and Collectors Included" lists the collectors with outlet counts. They are regenerated by `scripts/generate-sources.php` from the `apify-news-scraper` repo, so no separate `llm-sources.txt` exists
